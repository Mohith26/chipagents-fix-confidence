# Fix confirmation for ChipAgents RCA Triage

**Live demo:** https://mohith26.github.io/chipagents-fix-confidence/

ChipAgents' regression-triage flow ends with "fix → verification → final regression". This adds the step in between that nobody quantifies: **how many reruns prove a fix worked, and which ones.** For every failure bin it estimates the bug's per-seed failure rate from regression history, shows how much risk a single clean nightly actually leaves, and computes the cheapest set of fresh-seed reruns at the fix revision that brings the chance the bug is still there under a target (for example 5%), using RCA's own confidence as the prior. Bins too rare to confirm by reruns are flagged for a directed test instead. It runs on **real public data**: 4,089 OpenTitan nightly DV reports (Jan to Oct 2024, 36 IP regressions).

## How it works

1. **Data.** `scripts/list_nightlies.py` and `scripts/fetch_opentitan.py` read every dated report in the public `reports.opentitan.org` bucket and keep, per IP and nightly: each test's runs, passes and max runtime, and dvsim's failure buckets (signature, failing runs per test, witness seeds). Raw HTML is not stored.
2. **Bins.** Signatures are normalised (line numbers and literal numbers removed, xcelium "Exit reason" wrappers stripped) so code churn does not split a bin; infrastructure failures (job launch, dependent-job kills) are dropped.
3. **Exposure, not runs.** dvsim buckets a failing run by its first error, so a run that died on another bug or on infrastructure says nothing about this bin. Evidence counts only runs that passed or failed with this signature (the censoring fix moved the backtest more than any modelling change).
4. **Posterior.** Per test, the bug's per-seed failure rate gets a Beta(0.5 + fails, 0.5 + exposed − fails) posterior pooled over the last W nightlies (W = 16, chosen on the training split).
5. **Escape probability.** If the fix does not work, a plan of m<sub>t</sub> fresh seeds stays clean with probability ∏<sub>t</sub> B(a<sub>t</sub>, b<sub>t</sub> + m<sub>t</sub>) / B(a<sub>t</sub>, b<sub>t</sub>). Bayes with the prior π that the fix works (default 56.3%, ChipAgents RCA's published top-1 accuracy; set it from the RCA confidence score) gives the residual risk after a clean plan.
6. **Optimal plan.** Minimise Σ m<sub>t</sub> · runtime<sub>t</sub> subject to residual risk ≤ δ. Each log-escape term is a cumulant generating function in m, hence convex, so a greedy on (log-escape drop / CPU cost) traces the exact cost-risk frontier: every greedy prefix is optimal for the risk it reaches. A Lagrangian dual bound certifies the gap at the requested target and a branch and bound closes it (all 113 plans exact).
7. **Backtest.** For every time a signature fired at nightly r and was absent at r+1 although its tests ran, predict whether it returns within 10 nightlies: P(unfixed | clean) × P(fires again | unfixed), plus a re-emergence rate ρ for signatures that come back from a later change. W, π and ρ are fitted on nightlies before 2024-07-01 and scored on the rest.

The app (`index.html`, `app.js`, `styles.css`) is static, loads `data/app.json` (184 KB) and computes every number in the browser with `src/confirm.js`, the same module the tests and build script use.

## Product surface

- **RCA > Regression triage** (the existing view): failure bins by IP and kind, witness seeds, 30-nightly history.
- **RCA > Fix confirmation** (new): per-bin clean-nightly risk and optimal plan, verdict (nightly is enough / targeted reruns / directed test), target and fix-prior controls, search, filters, sorting, CSV export.
- **Bin detail** (`#/bin/<id>`): evidence table with 90% credible intervals, plan per test, comparison against "rerun witness seeds", "one clean nightly", "two clean nightlies", the cost-risk frontier, ready-to-run dvsim commands, JSON export, and a status flow (Approve plan → Plan ran clean / Failure reproduced) persisted in localStorage.
- **Backtest**: calibration plot, comparison against baselines, held-out events.
- Keyboard: `j`/`k`, `Enter`, `Esc`, `/`, `a` (approve), `⌘B` (sidebar), `?`.

## Run it

```
python3 scripts/list_nightlies.py && python3 scripts/fetch_opentitan.py   # optional: refresh data (about 1 minute)
node scripts/build.mjs                                                     # data/app.json + data/results.json
node --test test/*.test.mjs                                                # 14 tests
python3 -m http.server   # then open http://localhost:8000
```

Tests cover lgamma and Beta quantiles against closed forms, the escape term against numerical integration, convexity on random posteriors (property test), greedy-prefix optimality and exact optimality against brute force on random instances, a 20,000-draw simulation showing clean plans meet the residual-risk target, signature normalisation and censoring, and a headline test that rebuilds `results.json` from the committed data.

## Honest limitations

- **Within-revision model.** Seeds are independent draws at one revision, so the guarantee holds for reruns at the fix revision with p drawn from the posterior. Across nightlies the code changes; the backtest shows 71% of signatures come back even when the clean nightly made a quiet unfixed bug unlikely. That is why the plan runs at the fix revision and why the backtest model needs a re-emergence term ρ = 0.35.
- **The prior matters.** Residual risk depends on π. 56.3% is ChipAgents' published RCA top-1 accuracy on its benchmark, not a per-fix confidence; in production it would come from the RCA confidence score, which their blog says is calibrated.
- **Signatures are not root causes.** dvsim buckets by first error message; generic messages (CSR read mismatch, phase timeout) can hide several bugs and one bug can produce several messages. ChipAgents' AI binning pass would feed better bins into the same math.
- **Costs** use dvsim's max job runtime per test, an upper bound. dvsim lists at most five tests per bucket, so wide bins are truncated.
- **Calibration** is modest (AUC 0.68, Brier 0.171 vs 0.180 for the base rate); low-prediction events return more often than predicted.
- dvsim command paths for variant IPs (aes_masked, rom_ctrl_32kB, ...) follow OpenTitan's naming pattern but were not run.

## Prior art and novelty

Sequential testing and reliability demonstration ("how many failure-free trials prove a failure rate") are classical (zero-failure acceptance sampling, Bayesian reliability demonstration). Flaky-test work in software (for example rerun budgets in Google's and Meta's CI, DeFlaker, iDFlakies) decides whether a test is flaky, not how many seeds confirm a fix under a stated risk. Commercial verification managers (Synopsys Verdi/VC Execution Manager, Cadence vManager) and ChipAgents' own RCA Triage bin failures, pick witness simulations and rerun regressions, but none publicly quantifies the residual risk left by a clean rerun or optimises the confirmation plan. The contribution here is the product integration: posterior from regression history with censoring, a certified-optimal multi-test plan with RCA confidence as the prior, and a backtest on real nightly data.
